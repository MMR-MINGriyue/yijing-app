## iter28 历史屏搜索高亮

### 问题
屏 6 搜索框 input 时已过滤匹配的 hist-card, 但**没有视觉强调**匹配关键字. 用户难以一眼看出"哪条记录的哪个字段被命中".

### 修复
1. **CSS 新增**: `.hist-card.search-hit` (朱砂色边框 + 左侧朱砂渐变竖条) + `.hist-mark` (金色背景高亮关键字)
2. **renderOne() 增强**: 接受外部 `histKeyword` 闭包变量
   - 卡片 className 追加 `search-hit` (搜索时)
   - 卦名 `hist-name` 与问题 `hist-q` 通过 `highlight(text, kw)` 函数包裹匹配字符
3. **highlight() 安全函数**:
   ```js
   function highlight(text, kw) {
     const s = String(text == null ? '' : text);
     if (!kw) return escapeHtml(s);
     const lower = s.toLowerCase();
     const kwl = kw.toLowerCase();
     const idx = lower.indexOf(kwl);
     if (idx < 0) return escapeHtml(s);
     return escapeHtml(s.slice(0, idx)) +
       '<mark class="hist-mark">' + escapeHtml(s.slice(idx, idx + kw.length)) + '</mark>' +
       escapeHtml(s.slice(idx + kw.length));
   }
   ```
   - 先 escapeHtml 整段 + 中间匹配段也 escapeHtml, 防止用户输入 `<script>` 注入

### 效果 (截图)
- 搜「事业」: 2 张匹配卡, 卡内「事业」二字金色高亮 + 卡片左侧朱砂竖条
- 搜「感情」: 1 张匹配 (咸卦), 高亮一致
- 搜不存在: 0 张 + 「无 匹 配 记 录」空态
- 清空: mark + search-hit 全部消失, 恢复 7+ 张

### 调试坑

1. **测试受内置历史干扰**: 默认 YijingHistory.all() = localStorage + YIJING_DATA.HISTORY (concat). 测试用「事业」「乾」等通用关键字会被内置数据匹配, 数量不稳定. 改用独有标记 `TAG28` 隔离 (注入 4 条都含 TAG28), 测试只关心 TAG28 关键字的精确匹配数
2. **XSS 防护**: 搜索 `<script>alert(1)</script>` 时, escapeHtml 转义 `<` `>` 后, 中间匹配段也已 escapeHtml, 实际渲染为 `&lt;script&gt;alert(1)&lt;/script&gt;` — 既不执行又有可见文字. 测试断言无 pageerror ✓
3. **遗留 PNG 重复出现**: 之前清理过 `_ls1-fixed.png` 等, 这次又出现 (可能前次清理后 git add -A 又重新 add, 这次用 `git rm --cached` 显式从索引移除)
