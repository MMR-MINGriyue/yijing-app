# 2026-09-02 第三十一轮迭代 — Flutter 屏 4 卦辞解析重写 (v1.28.0)

## 背景

延续 iter30 Flutter MVVM 实验田, 用户要求重写屏 4「卦辞解析」——验证"数据展示型屏"的迁移成本. 与屏 5 区别: 屏 5 偏推演计算, 屏 4 偏大量文本质/爻辞展示.

## 数据扩展示意图 (迁移成本核心)

屏 4 数据需求 (vs 屏 5):
- 屏 5: 64 卦的 no/name/triU/triD/lines (64 行 = ~2KB)
- 屏 4: 加上 guaci/daxiang/intro/desc/triUN/triDN/yao[6].{n,q,d}

`extract-hex.js` 解析 HEX_LIBRARY (24-601 行, 64 卦) + HEX_EXTRA (604-668 行, no→{guaci/daxiang,intro}) 两段, 合并生成 `hex_library.dart`:
- 64 卦 × 7 个解析字段 + 6 爻 × 3 子字段
- 文件 38.6KB (vs 屏 5 的 5.7KB, **6.7x**)
- 包含 64 卦的卦辞 (乾坤"元亨利贞"等文言) + 大象传 (天行健/地势坤等) + 6 爻辞 + 白话解读

## 屏 4 Flutter 实现 (MVVM 严格分层)

```
lib/
├── data/hex_library.dart    64 卦完整数据 (从易道 data.js 自动提取, 38KB)
├── model/hex.dart            Hex 类 (增 en/desc/guaci/daxiang/intro/yao + title/virtue getter)
├── viewmodel/detail_viewmodel.dart   DetailViewModel (DetailTab enum, 收藏内存态)
├── view/detail_screen.dart   屏 4 UI (hero + 3 tabs + 建议 + 六爻解读 + 收藏星标)
└── main.dart                 双屏 Hub (IndexedStack + BottomNavBar 切换屏 4/5)
```

`main.dart` 改造: 从单一 TransformScreen → IndexedStack 双屏 Hub:
```dart
body: IndexedStack(index: _screen, children: [
  DetailScreen(vm: DetailViewModel(hexNo: 1)),  // 屏 4
  TransformScreen(vm: TransformViewModel()),     // 屏 5
]),
bottomNavigationBar: BottomNavigationBar(... '卦辞解析' / '变卦推演'),
```

## 关键设计决策

1. **数据格式扩展**: 单条 HexEntry 增加 11 个字段 (en/desc/triUN/triDN/guaci/daxiang/intro/yao[6]). 38KB 大小, 生成在编译期嵌入 const 列表
2. **Desc 拆分 helper**: `Hex.title` / `Hex.virtue` getter 解析 `desc = "乾为天 · 刚健中正"`, View 层直接用 `h.title` / `h.virtue` 不需手 split
3. **Tab 切换**: 单一 `DetailViewModel` 持 `_tab` 状态, View 监听 `widget.vm.addListener` 重建——MVVM 单向数据流
4. **收藏本地态**: 内存 `Set<int> _fav`, 持久化留空 (避免 dart:html 或加 shared_preferences 依赖, Flutter 实验田保持极简)
5. **六爻解读可滚动**: ListView 6 个 yao-row, 包含爻名/爻辞/白话, 与易道 yao-list 一致

## 屏 4 vs 屏 5 迁移成本对比

| 维度 | 屏 5 (iter30) | 屏 4 (iter31) |
|---|---|---|
| 数据大小 | 5.7KB (64 卦仅 lines/trigrams) | 38.6KB (64 卦完整文言) — **6.7x** |
| 数据来源 | HEX_LIBRARY 单一数组 | HEX_LIBRARY + HEX_EXTRA 两段 (正则 `no:{...}` 解析) |
| UI 组件 | 3 卡片 + 爻点击交互 | hero + 3 tabs + 6 爻卡 + 个性化建议 + 收藏星标 + 9 卡 — 翻倍 |
| ViewModel 复杂度 | 1 个 state (benNo/moving/result) | 2 个 state (hex + tab + 收藏 Set) |
| 验证数量 | 10 项 | 20 项 (10 项引擎 + 10 项屏 4 数据) |
| CI 编译 | 5 分钟 70MB APK | 1 分钟 70MB APK (缓存命中) |

## 结论: 数据展示型屏的迁移成本

- **数据搬运**是主要成本: 64 卦文言文本 ~30KB, 易道 data.js 自动提取到 Dart 一行代码搞定
- **UI 复杂度** 翻倍但架构不变 (MVVM 直接套), Flutter ListView + 条件渲染比手写 DOM 文本拼接清晰
- **编译/运行**成本不变, 都是 70MB debug APK
- **屏 4 + 屏 5 双屏 Hub 验证**: IndexedStack 切换保留各屏状态 (滚动位置/选中 tab 等), 接近原生 App 多页面体验
